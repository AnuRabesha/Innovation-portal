02 / 10
Problem Statement
Why This Portal?
Challenges faced before this system was built
📂
No Centralized RecordStudent achievements were scattered across spreadsheets, emails, and paper records with no single source of truth.
🔍
No VisibilityParents, faculty, and enterprises had no easy way to discover or verify student accomplishments.
📊
No AnalyticsDepartment had no data-driven insights on achievement trends, top performers, or category-wise performance.
🏆
No Recognition SystemOutstanding students were not ranked or recognized systematically based on verified achievements.
03 / 10
Objective
What We Built
A full-stack web portal with 4 user roles and complete achievement lifecycle management
🎯
Centralized Achievement Hub
Single platform to submit, verify, and showcase all student achievements across 17 categories.
👥
Multi-Portal Access
Separate portals for Students, Faculty, Parents, and Enterprise users with role-based access.
📈
Analytics Dashboard
Visual insights on achievement trends, batch-wise performance, and category breakdowns.
🏅
Scoring & Rankings
Automated 100-point scoring engine that ranks students based on verified achievements.

Technology Stack
Built With
Lightweight, no-framework approach — runs entirely in the browser
🌐
FrontendHTML5, CSS3, Vanilla JavaScript — no frameworks, fully responsive design.
🐍
Local ServerPython HTTP Server (port 8080) — serves all static files locally.
⚡
OTP BackendFastAPI (Python) on port 5000 — handles OTP generation and email delivery via Gmail SMTP.
💾
Data StorageSessionStorage for auth state. JS data store (data.js) simulates a backend database.
